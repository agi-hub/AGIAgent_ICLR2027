# Wiki-Evolve 统一叙事：从碎片创新到一条主线

> 本文将 `paper_innovation_points.md`（机制清单）、`paper_innovation_top.md`（四核心创新）、`memory_innovation_details.md`（11 条细节）中的碎片，整合为一条可讲通的主线。所有数字均有实验数据支撑（abl19/21/22 系列，GLM-5.2，6 游戏 × 10 迭代 × 110 步）。

## 一、一句话主线

**Agent 的学习应该发生在哪里？——不在参数里（梯度），不在会话里（反思），而在一个独立的、按认识论规则组织的外部知识库里。**

Wiki-Evolve = **把"科学知识生产"的制度搬到 Agent 记忆上**。整套系统是一个隐喻的逐条落实：

| 科学制度 | 系统实现 | 证据 |
|---|---|---|
| 实验记录本（永不涂改） | experiences 层 append-only | phase_m_prompt: "Keep ALL previous entries" |
| 综述论文（每轮重写） | knowledge 层 rewrite-from-scratch（≤800 词） | 同一 prompt L6 |
| 引用规范 | 每条知识强制 Evidence 链接（链接数=复现次数） | 实测 detective 24 步全部带引 |
| 可重复性要求 | 分数增量由代码确定性提取，LLM 只做合成 | `_pre_extract_score_actions` |
| 实验室安全条例 | FATAL 负向知识 + 工具层硬拦截 | 消融 -44%（Detective 297→165） |
| 同行评审置信度 | 验证标记编译进检索排序（conf 乘子） | `_parse_confidence` × 分层阈值 |
| 学科边界 | applies_to 软过滤（×0.3 降权不删除） | wiki_memory.py:604-619 |

### 2.1 核心是双层结构——不是认知模仿，是认识论分工

系统的持久记忆实际是**双层**（experiences / knowledge），划分标准不是 Tulving 的记忆分类学，而是**证据链上的角色**：

```
experiences (append-only)  =  原始证据 —— 审计基准，不可篡改
knowledge   (rewrite)      =  当前最优理论 —— 每轮基于全部证据重新生成
```

由此自然推出前文的结构创新：
- **物化视图性质**（details §1.1）：knowledge 理论上可从 experiences 完全重建——因为它的生成协议就是"读全部证据重写"。
- **Evidence 链接**（§1.2）：综述必须引用原始文献。

系统中还有一个 episode 内的 world model 图（WM graph，单局维护、随局丢弃），它是**在线工作记忆**而非持久知识层——实测它对性能无贡献（§三之附），叙事上定位为"构建了但未被采纳的设计空间探索"，不进入核心架构主张。

### 2.2 为什么重写而非增量更新？——理论更替无_PATCH

科学的知识更替方式是"新理论取代旧理论"，不是"给旧理论打补丁"。Rewrite-from-scratch（details §2.2）因此同时解决了三个工程问题：大小有界（防膨胀）、无冲突累积（错误条目不被重写即被遗忘）、新颖性偏置（每轮偏向当前最优压缩）。**冲突消解逻辑被生成协议吸收，无需实现**。

### 2.3 为什么代码提取分数、LLM 只做合成？——仪器读数不经人手

`_pre_extract_score_actions` 的信任边界（details §2.1）对应"仪器读数直接进论文，不靠回忆"。LLM 幻觉无法伪造 +10，因为它根本不接触数值事实的转写。

### 2.4 为什么 FATAL 是硬拦截？——安全条例是强制执行的不是建议的

知识库不是只读参考。FATAL 条目从语义标记被**编译为运行时约束**（details §3.1），对应"实验室条例由制度执行而非自觉"。这是与所有 prompt 注入式记忆使用的根本分化。

## 三、主线的实验叙事（四组数字讲完）

**故事线：钱应该投在哪一层？**

### 数字 1：基线校准——脚手架不值钱（abl22）

纯 ReAct（去掉 loop detection + 探索提示词）= **178.7**，反而高于带全套脚手架的 152.7。
→ 干预式行为提示词对强模型净贡献为负。**学习不能靠 prompt 工程**（对照 EvoTest 的 prompt 演化路线）。

### 数字 2：证据层就值大部分——append-only 日志 ≈ 88% 收益（abl21）

只允许查 experiences（无 knowledge、无 FATAL）= **379.5**（full 的 88%）。
→ 机制：curator 写 experience 时自发半蒸馏（Key finding 携带完整路线）。
**"有策展环节"比"策展产出什么层"更重要。**

### 数字 3：蒸馏的边际价值是任务依赖的——压缩何时回本（abl19 full vs abl21）

| Game | full | Exp-only | knowledge 增量 | 任务特征 |
|---|---|---|---|---|
| Detective | 297 | 273 | +9% | 线性宽容 |
| Library | 29.1 | 16.0 | **+82%** | 顺序敏感（give A before B） |
| Temple | 22.0 | 13.5 | **+63%** | 精确咒语序列 |
| TOTAL | 432.8 | 379.5 | +12% | |

→ 蒸馏回本的条件：**动作顺序约束跨多轮分散，只有重写式蒸馏能把它固化为显式规则**。这给出"何时需要记忆压缩"的首个任务维度定量刻画。

### 数字 4：护栏是保险不是引擎——FATAL 反事实

去掉 FATAL 拦截（其余不变）：Detective 297→165（**-44%**）；知识路径引导防 9/10 死亡，硬拦截兜底 5/10。
→ 编译式约束的定位：主引擎是知识检索，护栏负责 agent 偏离时的安全网。

### （附）诚实的负结果：WM 工作记忆未被采纳

WM-only = 180.1 ≈ 纯 ReAct 178.7（+1.4，噪声范围内）。诊断（60 局逐局核查）：query_wm 仅 15% 的局使用（prompt 从不引导、工具自然发现率低）、frontier 退化为全集（look/inventory 等 filler 动词永久占据 untried 列表，19/19 节点全标 frontier）、输出按访问次数排序对探索无指引、60 局中可归因于 WM 的得分仅 1 例（Zork3 play3：frontier 提示 "down" → +1）。结论：**与交互流冗余的记忆层没有生存空间**——admissible_commands（67% 的动作已带）+ 对话历史已覆盖 WM 的绝大部分信息，其独占信息（全图聚合）价值不足以驱动查询。论文处理：作为 negative result / design lesson 写入 discussion，不进入方法主张。

## 五、论文结构建议（按主线重排）

1. **Intro**：学习位置问题（上表的五行）。贡献 = 知识层学习 + 认识论制度设计 + 四组定量证据。
2. **Method**：不按记忆三层平铺，按**证据链生命周期**组织——
   - 4.1 记录（append-only experiences + 仪器化提取）
   - 4.2 综述（rewrite-from-scratch + Evidence 链接）
   - 4.3 执行（检索排序置信度 + FATAL 编译）
   - 4.4 边界（applies_to 软过滤；WM 作为讨论中的负结果，不单列方法小节）
3. **Experiments**：四组数字按"投在哪一层"递进（§三）；WM-only 条件作为负结果报告（180.1 vs 纯 ReAct 178.7）。
4. **Discussion**：何时需要蒸馏（任务结构依赖）；记忆层生存条件——WM 案例给出反例（信息与交互流冗余时无生存空间）。

**审稿人最可能的攻击点与回应**：
- "都是工程细节堆砌" → §二证明每个机制是同一认识论原则的推论，且各自有消融数字。
- "为什么只有两层？agent 不需要在线工作记忆吗？" → 我们实现了 WM 图层并做了完整消融（WM-only ≈ 基线），负结果 + 诊断（冗余性论证）比硬塞三层更有说服力。
- "与 SAMem 区别？" → 状态生命周期离散化 + 条件化保留 + 可重建性（物化视图）；SAMem 的 Q 值剪枝是删除式遗忘，无审计性。
